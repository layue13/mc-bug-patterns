# MC 模组缺陷范式

模组（以及原版）里反复出现的缺陷模式，写成**可供 AI 阅读代码时对照的范式**。
这里只有范式，不含规则、脚本、案例清单；具体判断由 AI 阅读目标代码完成。

## 怎么用

把 [`AGENTS.md`](AGENTS.md) 交给 AI，并指向要审查的仓库。AI 会按范式在代码里找形状、读上下文、给出有原文证据的结论。

## 范式

| 码 | 范式 | 一句话 |
|---|---|---|
| [D1](paradigms/D1.md) | 多视图状态不同步 | 同一份库存有两个可写视图，一个变了另一个还能用 |
| [D2](paradigms/D2.md) | 槽位与热键搬运 | 搬运时源槽没扣，或下标区间与背包重叠 |
| [D3](paradigms/D3.md) | 模拟与执行不一致 | 自动化先模拟再执行，两次结果/数量不一致 |
| [D4](paradigms/D4.md) | 别名与缺失拷贝 | 把可变对象当结果直接用，两处共享同一对象 |
| [D5](paradigms/D5.md) | 堆叠与携带状态 | 库存/NBT/实体携带的状态在转移时被复制 |
| [D6](paradigms/D6.md) | 重复产出 | 一个事件的多条路径各产出一份 |
| [D7](paradigms/D7.md) | 假定全量成功 | 忽略转移的实际量，按请求量记账 |
| [D8](paradigms/D8.md) | 方块搬迁与还原 | 带状态的方块被打包/重放时状态既带走又留下 |
| [G1](paradigms/G1.md) | 绕过保护检查 | 改世界的路径没经过领地/权限检查点 |
| [G2](paradigms/G2.md) | 免费常加载 | 区块加载无成本、无上限 |
| [G3](paradigms/G3.md) | 全局状态与平衡破坏 | 普通物品改全服天气/时间或给创造级能力 |
| [G4](paradigms/G4.md) | 信任边界 | 客户端数据、外部数据、依赖、身份被无条件信任 |
| [C1](paradigms/C1.md) | 服务端稳定性 | 空值、无上限、重入、数据膨胀导致崩溃卡顿 |

每个范式的文件包含：机理、读代码时找什么、确认条件、排除条件、典型修法、证据强度。

## 范式从哪来

- MC百科「MOD特性警示」176 条（bug.mcmod.cn）：逐条阅读并人工归类。
- 5 个开源模组（Mekanism、Applied Energistics 2、Create、Botania、Refined Storage）自 2021 年起的 1883 个修复提交：统计"修复时新增了什么写法"，对其中的复制类修复逐条读代码。D4（别名）由此得出。
- 这 5 个仓库的 GitHub issue（公开网页）：读了与复制相关的 issue 列表（标题与标签）和其中 6 个 issue 的正文。网页内容经抓取工具摘要，只用于提取机理，不用于计数。D7、D8、L2 主要由此得出。
- 原版缺陷跟踪（Mojira）的标题样本：只用来佐证方向，未做定量分析。

**证据强度**在每个范式文件里单独标注。D6、L1 证据较弱，只是值得检查的方向。
统计比较是探索性的（同时比较了 24 种写法，未做严格的多重检验校正）。

## 一个重要的负面结果

曾经为这些范式写过 Semgrep 规则，并用 186 个真实修复提交测试：在没参与调规则的留出仓库上，**47 个修复里 0 个被规则抓到**，真实的复制类修复一个都没覆盖。
原因是现实里的缺陷多是需要上下文才能判断的逻辑形状，而不是固定的语法形状。因此仓库不再提供规则，改为让 AI 读代码。
规则、测试、脚本和基准集仍在 git 历史中（提交 `366df48` 及之前），需要时可以取回。

## 局限

- 范式来自站点样本和 5 个大型开源模组，偏向 1.12.2–1.21 的 Forge/NeoForge 生态，对其他加载器和小型模组的代表性未知。
- 样本是"已被发现并修复的缺陷"，存在幸存者偏差。
- 没有测过 AI 按这些范式审查代码的准确率。
