# G4 后门 / RCE / 越权命令 / 未校验发包
规则：`mc-g4-op-grant-or-shell`（ERROR）、`mc-g4-packet-handler-unchecked-position`、`mc-g4-vulnerable-log4j`（ERROR）

## 判定目标
是否存在让**未授权方**获得 OP、执行系统命令或让服务端信任客户端数据的路径。这是优先级最高的一类，宁可多复核。

## 必须读的代码
命中处全文 + 所有调用者 + 触发条件（硬编码的玩家名？配置？命令权限？）。

## 确认条件
- op / shell：触发条件与**身份无关**或依赖**硬编码用户名/哈希/远程字符串**；或没有权限检查；或参数来自网络/聊天/NBT。
- 发包：C2S 包处理器用包内坐标/ID 访问世界或库存，缺少「是否已加载」「距离」「玩家当前打开的菜单是否匹配」中的**所有**必要检查（仅有其一不够时标 needs_human 并说明缺哪个）。
- log4j：依赖版本 ≤ 2.16 且**不是**由加载器/启动器提供的受保护版本（模组自带 shaded 旧版是真问题）。

## 排除条件
- OP 授予在 `/op` 命令实现或管理员专用 GUI 内，且受 `hasPermissions(>=2)` 保护。
- `ProcessBuilder`/`exec` 用于开发期工具（`src/test`、gradle 脚本），不进发布 jar。
- log4j 仅为 `compileOnly`，运行时由游戏提供。

## 需要人工
硬编码的名字/域名是否属于项目所有者；依赖是否被 shadow。

## 若 confirmed
**不要**在公开 issue 里贴细节；按组织安全流程私下上报。reasoning 里只写必要定位信息。
