# D5 流体与容量边界 → 复制
规则：`mc-d5-fluid-handler-ignores-action`（HIGH）

## 判定目标
`fill/drain` 的模拟与执行是否一致，容量边界是否正确。

## 必须读的代码
命中方法全文 + tank 字段类型/容量定义。

## 确认条件
1. 方法实际改变流体量，却不依赖 `FluidAction`/`doFill`/`doDrain` → 模拟也会改状态。
2. 或：返回值大于实际变化（返回了 `resource.getAmount()` 而实际只灌入 `min(...)`）。
3. 边界：容量为 C 时输入 C、C+1、1000mB 与单位换算（如 mB 与桶）是否混淆。

## 排除条件
- 纯委托给内部 tank 并传入了 action（规则可能漏判，检查）。
- 只读/拒绝型处理器（永远返回 0 / EMPTY 且不改状态）。

## 建议修法
同 D3；属性测试覆盖 0 / 容量 / 容量+1 / 极大值。

## 对应站点案例
液体漏斗(15)、装瓶机(96)、木桶(94)、流体球(105)。
