# C3 数值失效

**一句话**：`NaN`、无穷大或溢出的数值被写进持久状态（生命值、伤害、治疗、属性、数量），状态因此永久损坏——实体无法死亡、无法被治疗，或持续报错。

**机理**：浮点运算遇到 0/0、无穷减无穷、极端乘法时得到 `NaN`；`NaN` 与任何数比较都为假，于是"生命值 ≤ 0 就死亡"这类判断永远不成立，实体变成"假死"。整数运算在大数量下溢出成负数或回绕。一旦写进存档，之后每次读取都带着坏值。

**读代码时找什么**
- 伤害、治疗、属性修饰、吸血、百分比计算：除数可能为 0？乘数可能极大？
- 把计算结果直接写入生命值/吸收量/属性/计数的位置：写入前是否校验有限性与范围。
- 对外部输入（配置、数据包、命令参数）做的算术。
- 整数用于累加数量、体积、金额：是否可能超过上限。
- 对 `NaN` 的比较写法（`x == x`、`isNaN`）是否被误用或缺失。

**确认条件**：写出一组具体输入（0 除数、极大伤害、极大倍率），说明经过哪几步得到 `NaN`/溢出值，以及它被写进了哪个状态。

**排除条件**：写入点前已有有限性/范围校验；该数值只用于瞬时显示，不写入状态。

**典型修法**：在写入状态的入口（伤害/治疗事件、属性设置）检查 `NaN`/无穷并取消或修复；对数量使用足够宽的类型或做饱和运算；修复已损坏的状态（把 `NaN` 生命值重置）。

**证据强度**：中到强。至少 5 个互不相关的专门修复模组（均针对"NaN 生命值/伤害溢出"），其中一个读过实现；MC百科另有 1 条（首领的特殊机制造成无法正常死亡）。
